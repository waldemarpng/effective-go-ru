# Форматирование

[оригинал](https://go.dev/doc/effective_go#formatting)

Споры о форматировании самые жаркие, но сами по себе они значат меньше всего. Люди могут привыкнуть к разным стилям, но лучше, если им не придётся, и на эту тему уйдёт меньше времени, если все придерживаются одного стиля. Вопрос в том, как прийти к этой утопии без длинного предписывающего гайда.

В Go мы выбираем необычный путь и отдаём большую часть форматирования машине. Программа `gofmt` (она же доступна как `go fmt`, которая работает на уровне пакета, а не файла) читает программу на Go и выдаёт исходник в стандартном стиле отступов и вертикального выравнивания, сохраняя и при необходимости переформатируя комментарии. Если не знаете, как оформить новую ситуацию с вёрсткой, запустите `gofmt`; если ответ кажется неверным, переставьте программу (или заведите баг про `gofmt`), а не обходите инструмент.

Например, не нужно тратить время на выравнивание комментариев к полям структуры. `Gofmt` сделает это за вас. Для объявления

```
type T struct {
    name string // name of the object
    value int // its value
}
```

`gofmt` выровняет колонки:

```
type T struct {
    name    string // name of the object
    value   int    // its value
}
```

Весь код Go в стандартных пакетах отформатирован `gofmt`.

Некоторые детали форматирования всё же остаются. Кратко:

**Отступы.** Мы используем табы, и `gofmt` по умолчанию их выдаёт. Пробелы — только если иначе нельзя.

**Длина строки.** В Go нет ограничения на длину строки. Не беспокойтесь, что не влезет в перфокарту. Если строка кажется слишком длинной, перенесите её и сделайте отступ ещё одним табом.

**Скобки.** В Go меньше скобок, чем в C и Java: у управляющих конструкций (`if`, `for`, `switch`) скобок в синтаксисе нет. Иерархия приоритета операторов короче и яснее, поэтому

```
x<<8 + y<<16
```

означает то, что подразумевают пробелы, в отличие от других языков.
