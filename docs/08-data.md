## Выделение через `new`

[оригинал](https://go.dev/doc/effective_go#allocation_new)

В Go два примитива выделения памяти — встроенные функции `new` и `make`. Они делают разное и применимы к разным типам, что может путать, но правила простые. Сначала о `new`. Это встроенная функция, которая выделяет память, но в отличие от одноимённых средств в некоторых других языках она не инициализирует память, а только обнуляет её. То есть `new(T)` выделяет обнулённое хранилище для новой переменной типа `T` и возвращает её адрес, значение типа `*T`. В терминах Go она возвращает указатель на только что выделенное нулевое значение типа `T`.

Начиная с Go 1.26, `new` также принимает (значимое) выражение как аргумент: оно задаёт начальное значение переменной. Например, `new(int64(300))` выделяет новую переменную типа `int64`, инициализированную значением 300, и возвращает её адрес.

> **Сейчас.** Это одно из редких поздних уточнений в самом Effective Go. Подробности — в [Go 1.26 Release Notes](https://go.dev/doc/go1.26).

Поскольку память, которую возвращает `new`, обнулена, при проектировании структур данных полезно устроить так, чтобы нулевое значение каждого типа можно было использовать без дальнейшей инициализации. Тогда пользователь структуры может создать её через `new` и сразу работать. Например, документация `bytes.Buffer` говорит, что «нулевое значение `Buffer` — пустой буфер, готовый к использованию». Аналогично у `sync.Mutex` нет явного конструктора или метода `Init`. Нулевое значение `sync.Mutex` определено как незаблокированный мьютекс.

Свойство «нулевое значение уже полезно» транзитивно. Рассмотрим это объявление типа.

```
type SyncedBuffer struct {
    lock    sync.Mutex
    buffer  bytes.Buffer
}
```

Значения типа `SyncedBuffer` тоже готовы к использованию сразу после выделения или просто объявления. В следующем фрагменте и `p`, и `v` будут работать без дополнительных приготовлений.

```
p := new(SyncedBuffer)  // type *SyncedBuffer
var v SyncedBuffer      // type  SyncedBuffer
```

## Конструкторы и составные литералы

[оригинал](https://go.dev/doc/effective_go#composite_literals)

Иногда нулевого значения недостаточно, и нужен инициализирующий конструктор, как в этом примере, выведенном из пакета `os`.

```
func NewFile(fd int, name string) *File {
    if fd < 0 {
        return nil
    }
    f := new(File)
    f.fd = fd
    f.name = name
    f.dirinfo = nil
    f.nepipe = 0
    return f
}
```

Тут много шаблона. Можно упростить составным литералом — выражением, которое каждый раз при вычислении создаёт новый экземпляр.

```
func NewFile(fd int, name string) *File {
    if fd < 0 {
        return nil
    }
    f := File{fd, name, nil, 0}
    return &f
}
```

Заметьте: в отличие от C совершенно нормально вернуть адрес локальной переменной; хранилище, связанное с переменной, переживает возврат из функции. Более того, взятие адреса составного литерала каждый раз выделяет свежий экземпляр, так что последние две строки можно объединить.

```
    return &File{fd, name, nil, 0}
```

Поля составного литерала идут по порядку и должны быть все. Однако если явно пометить элементы парами поле`:` значение, инициализаторы могут идти в любом порядке, а пропущенные останутся нулевыми значениями. Поэтому можно сказать

```
    return &File{fd: fd, name: name}
```

В предельном случае, если в составном литерале нет полей вовсе, он создаёт нулевое значение типа. Выражения `new(File)` и `&File{}` эквивалентны.

Составные литералы можно создавать и для массивов, слайсов и map; метками полей тогда будут индексы или ключи map. В этих примерах инициализация работает независимо от значений `Enone`, `Eio` и `Einval`, лишь бы они были различны.

```
a := [...]string   {Enone: "no error", Eio: "Eio", Einval: "invalid argument"}
s := []string      {Enone: "no error", Eio: "Eio", Einval: "invalid argument"}
m := map[int]string{Enone: "no error", Eio: "Eio", Einval: "invalid argument"}
```

## Выделение через `make`

[оригинал](https://go.dev/doc/effective_go#allocation_make)

Вернёмся к выделению. Встроенная функция `make(T, ` args`)` служит другой цели, чем `new(T)`. Она создаёт только слайсы, map и каналы и возвращает инициализированное (не обнулённое) значение типа `T` (не `*T`). Различие нужно потому, что эти три типа под капотом — ссылки на структуры данных, которые нужно инициализировать до использования. Слайс, например, — дескриптор из трёх элементов: указатель на данные (внутри массива), длина и ёмкость; пока они не инициализированы, слайс — `nil`. Для слайсов, map и каналов `make` инициализирует внутреннюю структуру и готовит значение к использованию. Например,

```
make([]int, 10, 100)
```

выделяет массив из 100 int и затем создаёт структуру слайса длиной 10 и ёмкостью 100, указывающую на первые 10 элементов массива. (При создании слайса ёмкость можно опустить; см. раздел про слайсы.) Напротив, `new([]int)` возвращает указатель на только что выделенную обнулённую структуру слайса, то есть указатель на значение `nil`‑слайса.

Эти примеры показывают разницу между `new` и `make`.

```
var p *[]int = new([]int)       // allocates slice structure; *p == nil; rarely useful
var v  []int = make([]int, 100) // the slice v now refers to a new array of 100 ints

// Unnecessarily complex:
var p *[]int = new([]int)
*p = make([]int, 100, 100)

// Idiomatic:
v := make([]int, 100)
```

Помните: `make` применим только к map, слайсам и каналам и не возвращает указатель. Чтобы получить явный указатель, выделяйте через `new` или явно берите адрес переменной.

## Массивы

[оригинал](https://go.dev/doc/effective_go#arrays)

Массивы полезны, когда планируешь подробную раскладку памяти, и иногда помогают избежать выделения, но в первую очередь это строительный блок для слайсов — темы следующего раздела. Чтобы заложить основу, несколько слов о массивах.

Между тем, как массивы работают в Go и в C, есть важные различия. В Go:

- Массивы — значения. Присваивание одного массива другому копирует все элементы.
- В частности, если передать массив в функцию, она получит копию массива, а не указатель на него.
- Размер массива — часть его типа. Типы `[10]int` и `[20]int` различны.

Свойство значения бывает полезно, но и дорого; если нужно поведение и эффективность как в C, можно передать указатель на массив.

```
func Sum(a *[3]float64) (sum float64) {
    for _, v := range *a {
        sum += v
    }
    return
}

array := [...]float64{7.0, 8.5, 9.1}
x := Sum(&array)  // Note the explicit address-of operator
```

Но даже этот стиль не идиоматичен для Go. Используйте слайсы.

## Слайсы

[оригинал](https://go.dev/doc/effective_go#slices)

Слайсы оборачивают массивы и дают более общий, мощный и удобный интерфейс к последовательностям данных. Кроме элементов с явной размерностью вроде матриц преобразований, большая часть работы с массивами в Go делается слайсами, а не простыми массивами.

Слайсы держат ссылки на подлежащий массив, и если присвоить один слайс другому, оба ссылаются на один массив. Если функция принимает аргумент‑слайс, изменения элементов слайса будут видны вызывающему — аналогично передаче указателя на подлежащий массив. Поэтому функция `Read` может принять аргумент‑слайс вместо указателя и счётчика; длина внутри слайса задаёт верхний предел, сколько данных читать. Вот сигнатура метода `Read` типа `File` в пакете `os`:

```
func (f *File) Read(buf []byte) (n int, err error)
```

Метод возвращает число прочитанных байт и значение ошибки, если оно есть. Чтобы прочитать в первые 32 байта большего буфера `buf`, «нарежьте» буфер (здесь slice — глагол).

```
    n, err := f.Read(buf[0:32])
```

Такая нарезка обычна и эффективна. Если на минуту отложить эффективность, следующий фрагмент тоже прочитает первые 32 байта буфера.

```
    var n int
    var err error
    for i := 0; i < 32; i++ {
        nbytes, e := f.Read(buf[i:i+1])  // Read one byte.
        n += nbytes
        if nbytes == 0 || e != nil {
            err = e
            break
        }
    }
```

Длину слайса можно менять, пока она умещается в пределы подлежащего массива; просто присвойте его слайсу самого себя. Ёмкость слайса, доступная встроенной функцией `cap`, сообщает максимальную длину, которую слайс может принять. Вот функция, которая дописывает данные в слайс. Если данные превышают ёмкость, слайс перевыделяется. Результат возвращается. Функция использует тот факт, что `len` и `cap` законны для `nil`‑слайса и возвращают 0.

```
func Append(slice, data []byte) []byte {
    l := len(slice)
    if l + len(data) > cap(slice) {  // reallocate
        // Allocate double what's needed, for future growth.
        newSlice := make([]byte, (l+len(data))*2)
        // The copy function is predeclared and works for any slice type.
        copy(newSlice, slice)
        slice = newSlice
    }
    slice = slice[0:l+len(data)]
    copy(slice[l:], data)
    return slice
}
```

Слайс нужно вернуть, потому что хотя `Append` может менять элементы `slice`, сам слайс (структура времени выполнения с указателем, длиной и ёмкостью) передаётся по значению.

Идея дописывания в слайс настолько полезна, что её фиксирует встроенная функция `append`. Чтобы понять устройство этой функции, нужно ещё немного сведений, поэтому мы к ней вернёмся позже.

> **Сейчас.** Для типичных операций со слайсами есть пакет [`slices`](https://pkg.go.dev/slices).

## Двумерные слайсы

[оригинал](https://go.dev/doc/effective_go#two_dimensional_slices)

Массивы и слайсы Go одномерны. Чтобы получить эквивалент двумерного массива или слайса, нужно определить массив массивов или слайс слайсов, вот так:

```
type Transform [3][3]float64  // A 3x3 array, really an array of arrays.
type LinesOfText [][]byte     // A slice of byte slices.
```

Поскольку длина слайсов переменная, внутренние слайсы могут быть разной длины. Это обычная ситуация, как в нашем примере `LinesOfText`: у каждой строки своя длина.

```
text := LinesOfText{
    []byte("Now is the time"),
    []byte("for all good gophers"),
    []byte("to bring some fun to the party."),
}
```

Иногда нужно выделить двумерный слайс — например, при обработке строк пикселей. Есть два способа. Один — выделять каждый слайс независимо; другой — выделить один массив и направить в него отдельные слайсы. Что выбрать, зависит от приложения. Если слайсы могут расти или сжиматься, их стоит выделять независимо, чтобы не затереть следующую строку; если нет, эффективнее построить объект одним выделением. Для справки — наброски обоих методов. Сначала по одной строке:

```
// Allocate the top-level slice.
picture := make([][]uint8, YSize) // One row per unit of y.
// Loop over the rows, allocating the slice for each row.
for i := range picture {
    picture[i] = make([]uint8, XSize)
}
```

И теперь одним выделением, нарезанным на строки:

```
// Allocate the top-level slice, the same as before.
picture := make([][]uint8, YSize) // One row per unit of y.
// Allocate one large slice to hold all the pixels.
pixels := make([]uint8, XSize*YSize) // Has type []uint8 even though picture is [][]uint8.
// Loop over the rows, slicing each row from the front of the remaining pixels slice.
for i := range picture {
    picture[i], pixels = pixels[:XSize], pixels[XSize:]
}
```

## Map

[оригинал](https://go.dev/doc/effective_go#maps)

Map — удобная и мощная встроенная структура, которая связывает значения одного типа (ключ) со значениями другого (элемент или значение). Ключ может быть любого типа, для которого определён оператор равенства: целые, числа с плавающей точкой и комплексные, строки, указатели, интерфейсы (пока динамический тип поддерживает равенство), структуры и массивы. Слайсы нельзя использовать как ключи map, потому что равенство для них не определено. Как и слайсы, map держат ссылки на подлежащую структуру данных. Если передать map в функцию, которая меняет содержимое, изменения будут видны вызывающему.

Map можно строить обычным синтаксисом составных литералов с парами ключ‑значение через двоеточие, так что их легко собрать при инициализации.

```
var timeZone = map[string]int{
    "UTC":  0*60*60,
    "EST": -5*60*60,
    "CST": -6*60*60,
    "MST": -7*60*60,
    "PST": -8*60*60,
}
```

Присваивание и выборка значений map синтаксически выглядят так же, как у массивов и слайсов, только индекс не обязан быть целым.

```
offset := timeZone["EST"]
```

Попытка взять значение map по ключу, которого в map нет, вернёт нулевое значение типа элементов. Например, если в map лежат целые, поиск несуществующего ключа вернёт `0`. Множество можно реализовать как map со значением типа `bool`. Чтобы положить значение во множество, поставьте запись в `true`, а затем проверяйте простой индексацией.

```
attended := map[string]bool{
    "Ann": true,
    "Joe": true,
    ...
}

if attended[person] { // will be false if person is not in the map
    fmt.Println(person, "was at the meeting")
}
```

Иногда нужно отличить отсутствующую запись от нулевого значения. Есть ли запись для `"UTC"`, или это 0, потому что ключа в map нет? Различить можно формой множественного присваивания.

```
var seconds int
var ok bool
seconds, ok = timeZone[tz]
```

По очевидным причинам это называют идиомой «comma ok». В этом примере, если `tz` есть, `seconds` получит нужное значение и `ok` будет true; если нет, `seconds` станет нулём, а `ok` — false. Вот функция, которая собирает это вместе с понятным сообщением об ошибке:

```
func offset(tz string) int {
    if seconds, ok := timeZone[tz]; ok {
        return seconds
    }
    log.Println("unknown time zone:", tz)
    return 0
}
```

Чтобы проверить наличие в map, не заботясь о самом значении, вместо обычной переменной для значения можно использовать пустой идентификатор (`_`).

```
_, present := timeZone[tz]
```

Чтобы удалить запись, используйте встроенную функцию `delete`: аргументы — map и ключ. Это безопасно даже если ключа в map уже нет.

```
delete(timeZone, "PDT")  // Now on Standard Time
```

> **Сейчас.** Для типичных операций с map есть пакет [`maps`](https://pkg.go.dev/maps).

## Печать

[оригинал](https://go.dev/doc/effective_go#printing)

Форматированная печать в Go похожа на семейство `printf` в C, но богаче и более общая. Функции живут в пакете `fmt` и имеют имена с заглавной буквы: `fmt.Printf`, `fmt.Fprintf`, `fmt.Sprintf` и так далее. Строковые функции (`Sprintf` и др.) возвращают строку, а не заполняют предоставленный буфер.

Строку формата давать не обязательно. Для каждой из `Printf`, `Fprintf` и `Sprintf` есть ещё пара функций, например `Print` и `Println`. Они не берут строку формата, а порождают формат по умолчанию для каждого аргумента. Версии `Println` ещё вставляют пробел между аргументами и добавляют перевод строки, а версии `Print` добавляют пробелы, только если ни один из соседних операндов не строка. В этом примере каждая строка даёт один и тот же вывод.

```
fmt.Printf("Hello %d\n", 23)
fmt.Fprint(os.Stdout, "Hello ", 23, "\n")
fmt.Println("Hello", 23)
fmt.Println(fmt.Sprint("Hello ", 23))
```

Функции форматированной печати `fmt.Fprint` и родственники первым аргументом берут любой объект, который реализует интерфейс `io.Writer`; знакомые экземпляры — переменные `os.Stdout` и `os.Stderr`.

Здесь начинается расхождение с C. Во‑первых, числовые форматы вроде `%d` не принимают флаги знаковости или размера; вместо этого процедуры печати берут эти свойства из типа аргумента.

```
var x uint64 = 1<<64 - 1
fmt.Printf("%d %x; %d %x\n", x, x, int64(x), int64(x))
```

печатает

```
18446744073709551615 ffffffffffffffff; -1 -1
```

Если нужна просто конвертация по умолчанию, например десятичная для целых, можно использовать всеядный формат `%v` (от «value»); результат ровно тот, что дали бы `Print` и `Println`. Более того, этот формат печатает любое значение, даже массивы, слайсы, структуры и map. Вот оператор печати для map часовых поясов из предыдущего раздела.

```
fmt.Printf("%v\n", timeZone)  // or just fmt.Println(timeZone)
```

что даёт вывод:

```
map[CST:-21600 EST:-18000 MST:-25200 PST:-28800 UTC:0]
```

Для map `Printf` и родственники сортируют вывод лексикографически по ключу.

При печати структуры модифицированный формат `%+v` подписывает поля именами, а для любого значения альтернативный формат `%#v` печатает значение в полном синтаксисе Go.

```
type T struct {
    a int
    b float64
    c string
}
t := &T{ 7, -2.35, "abc\tdef" }
fmt.Printf("%v\n", t)
fmt.Printf("%+v\n", t)
fmt.Printf("%#v\n", t)
fmt.Printf("%#v\n", timeZone)
```

печатает

```
&{7 -2.35 abc   def}
&{a:7 b:-2.35 c:abc     def}
&main.T{a:7, b:-2.35, c:"abc\tdef"}
map[string]int{"CST":-21600, "EST":-18000, "MST":-25200, "PST":-28800, "UTC":0}
```

(Заметьте амперсанды.) Этот формат в кавычках доступен и через `%q` для значения типа `string` или `[]byte`. Альтернативный формат `%#q` по возможности использует обратные кавычки. (Формат `%q` также применим к целым и рунам и даёт константу руны в одинарных кавычках.) Кроме того, `%x` работает на строках, массивах и слайсах байт, как и на целых, порождая длинную шестнадцатеричную строку, а с пробелом в формате (`% x`) ставит пробелы между байтами.

Ещё один удобный формат — `%T`, который печатает тип значения.

```
fmt.Printf("%T\n", timeZone)
```

печатает

```
map[string]int
```

Если нужно управлять форматом по умолчанию для своего типа, достаточно определить на типе метод с сигнатурой `String() string`. Для нашего простого типа `T` это может выглядеть так.

```
func (t *T) String() string {
    return fmt.Sprintf("%d/%g/%q", t.a, t.b, t.c)
}
fmt.Printf("%v\n", t)
```

чтобы напечатать в формате

```
7/-2.35/"abc\tdef"
```

(Если нужно печатать значения типа `T` так же, как указатели на `T`, получатель `String` должен быть value‑типа; в этом примере взят указатель, потому что для структур это эффективнее и идиоматичнее. См. раздел ниже про [получатели‑указатели и получатели‑значения](10-methods.md).)

Наш метод `String` может вызывать `Sprintf`, потому что процедуры печати полностью реентерабельны и их можно так оборачивать. Есть одна важная деталь: не стройте метод `String`, вызывая `Sprintf` так, что он бесконечно вернётся в ваш `String`. Это случится, если вызов `Sprintf` попытается напечатать получатель напрямую как строку, что снова вызовет метод. Это частая и лёгкая ошибка, как показывает пример.

```
type MyString string

func (m MyString) String() string {
    return fmt.Sprintf("MyString=%s", m) // Error: will recur forever.
}
```

Исправить тоже легко: преобразуйте аргумент к базовому строковому типу, у которого этого метода нет.

```
type MyString string
func (m MyString) String() string {
    return fmt.Sprintf("MyString=%s", string(m)) // OK: note conversion.
}
```

В разделе про инициализацию увидим другой приём, который избегает этой рекурсии.

Ещё один приём печати — передать аргументы одной процедуры печати напрямую другой. Сигнатура `Printf` использует тип `...interface{}` для последнего аргумента, чтобы после формата могло появиться произвольное число параметров произвольного типа.

```
func Printf(format string, v ...interface{}) (n int, err error) {
```

Внутри функции `Printf` `v` ведёт себя как переменная типа `[]interface{}`, но если её передать другой вариативной функции, она ведёт себя как обычный список аргументов. Вот реализация функции `log.Println`, которой мы пользовались выше. Она передаёт аргументы напрямую в `fmt.Sprintln` для собственно форматирования.

```
// Println prints to the standard logger in the manner of fmt.Println.
func Println(v ...interface{}) {
    std.Output(2, fmt.Sprintln(v...))  // Output takes parameters (int, string)
}
```

Мы пишем `...` после `v` во вложенном вызове `Sprintln`, чтобы сказать компилятору считать `v` списком аргументов; иначе он передал бы `v` как один аргумент‑слайс.

О печати есть ещё больше, чем мы здесь покрыли. Подробности — в документации `godoc` пакета `fmt`.

> **Сейчас.** Документацию пакета смотрите через `go doc` или на [pkg.go.dev/fmt](https://pkg.go.dev/fmt). Для структурированных логов есть [`log/slog`](https://pkg.go.dev/log/slog).

Кстати, параметр `...` может быть конкретного типа, например `...int` для функции min, которая выбирает наименьшее из списка целых:

```
func Min(a ...int) int {
    min := int(^uint(0) >> 1)  // largest int
    for _, i := range a {
        if i < min {
            min = i
        }
    }
    return min
}
```

> **Сейчас.** В языке есть встроенные `min` и `max`. См. [Go 1.21 Release Notes](https://go.dev/doc/go1.21).

## Append

[оригинал](https://go.dev/doc/effective_go#append)

Теперь у нас есть недостающий кусок, чтобы объяснить устройство встроенной функции `append`. Сигнатура `append` отличается от нашей самодельной `Append` выше. Схематически она такая:

```
func append(slice []T, elements ...T) []T
```

где T — заполнитель для любого данного типа. На самом деле нельзя написать на Go функцию, в которой тип `T` определяет вызывающий. Поэтому `append` встроен: ему нужна поддержка компилятора.

> **Сейчас.** С дженериками такие функции писать можно. См. [Tutorial: generics](https://go.dev/doc/tutorial/generics) и [Tour: Generics](https://go.dev/tour/generics/1). `append` по‑прежнему встроенный.

Что делает `append` — дописывает элементы в конец слайса и возвращает результат. Результат нужно вернуть, потому что, как и у нашей рукописной `Append`, подлежащий массив может измениться. Этот простой пример

```
x := []int{1,2,3}
x = append(x, 4, 5, 6)
fmt.Println(x)
```

печатает `[1 2 3 4 5 6]`. Так что `append` работает немного как `Printf`, собирая произвольное число аргументов.

Но что, если мы хотим сделать то, что делает наша `Append`, и дописать слайс к слайсу? Легко: используйте `...` в месте вызова, как мы делали в вызове `Output` выше. Этот фрагмент даёт тот же вывод, что и предыдущий.

```
x := []int{1,2,3}
y := []int{4,5,6}
x = append(x, y...)
fmt.Println(x)
```

Без этого `...` код не скомпилируется: типы не сойдутся; `y` не типа `int`.
