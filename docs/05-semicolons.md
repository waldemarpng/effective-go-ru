# Точки с запятой

[оригинал](https://go.dev/doc/effective_go#semicolons)

Как и в C, формальная грамматика Go завершает операторы точкой с запятой, но в отличие от C эти точки с запятой в исходнике не видны. Вместо этого лексер по простому правилу вставляет их сам при сканировании, так что входной текст почти свободен от них.

Правило такое. Если последний токен перед переводом строки — идентификатор (включая слова вроде `int` и `float64`), базовый литерал вроде числа или строковой константы либо один из токенов

```
break continue fallthrough return ++ -- ) }
```

лексер всегда вставляет после этого токена точку с запятой. Коротко: «если перевод строки стоит после токена, которым мог бы закончиться оператор, вставь точку с запятой».

Точку с запятой можно опустить и сразу перед закрывающей фигурной скобкой, так что оператор вроде

```
    go func() { for { dst <- <-src } }()
```

точек с запятой не требует. В идиоматичных программах на Go точки с запятой стоят в основном в заголовках цикла `for`, чтобы разделить инициализатор, условие и продолжение. Они также нужны, чтобы разделить несколько операторов в одной строке, если вы так пишете.

Следствие правил вставки: открывающую скобку управляющей конструкции (`if`, `for`, `switch` или `select`) нельзя ставить на следующей строке. Если так сделать, перед скобкой вставится точка с запятой, и это может дать нежелательный эффект. Пишите так:

```
if i < f() {
    g()
}
```

а не так:

```
if i < f()  // wrong!
{           // wrong!
    g()
}
```
