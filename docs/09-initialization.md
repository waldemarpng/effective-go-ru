# Инициализация

[оригинал](https://go.dev/doc/effective_go#initialization)

Хотя на первый взгляд инициализация в Go не очень отличается от C или C++, она мощнее. Сложные структуры можно строить при инициализации, а вопросы порядка между инициализируемыми объектами, даже из разных пакетов, решаются правильно.

## Константы

[оригинал](https://go.dev/doc/effective_go#constants)

Константы в Go — именно константы. Они создаются во время компиляции, даже если определены как локальные в функциях, и могут быть только числами, символами (рунами), строками или булевыми. Из‑за ограничения времени компиляции выражения, которые их определяют, должны быть константными, вычислимыми компилятором. Например, `1<<3` — константное выражение, а `math.Sin(math.Pi/4)` — нет, потому что вызов `math.Sin` должен произойти во время выполнения.

В Go перечислимые константы создают перечислителем `iota`. Поскольку `iota` может быть частью выражения, а выражения неявно повторяются, легко строить замысловатые наборы значений.

```
type ByteSize float64

const (
    _           = iota // ignore first value by assigning to blank identifier
    KB ByteSize = 1 << (10 * iota)
    MB
    GB
    TB
    PB
    EB
    ZB
    YB
)
```

Возможность повесить метод вроде `String` на любой пользовательский тип позволяет произвольным значениям автоматически форматировать себя для печати. Чаще всего это применяют к структурам, но приём полезен и для скалярных типов, например чисел с плавающей точкой вроде `ByteSize`.

```
func (b ByteSize) String() string {
    switch {
    case b >= YB:
        return fmt.Sprintf("%.2fYB", b/YB)
    case b >= ZB:
        return fmt.Sprintf("%.2fZB", b/ZB)
    case b >= EB:
        return fmt.Sprintf("%.2fEB", b/EB)
    case b >= PB:
        return fmt.Sprintf("%.2fPB", b/PB)
    case b >= TB:
        return fmt.Sprintf("%.2fTB", b/TB)
    case b >= GB:
        return fmt.Sprintf("%.2fGB", b/GB)
    case b >= MB:
        return fmt.Sprintf("%.2fMB", b/MB)
    case b >= KB:
        return fmt.Sprintf("%.2fKB", b/KB)
    }
    return fmt.Sprintf("%.2fB", b)
}
```

Выражение `YB` печатается как `1.00YB`, а `ByteSize(1e13)` — как `9.09TB`.

Использование здесь `Sprintf` для метода `String` у `ByteSize` безопасно (не уходит в бесконечную рекурсию) не из‑за преобразования, а потому что вызывается `Sprintf` с `%f`, а это не строковый формат: `Sprintf` вызывает метод `String` только когда хочет строку, а `%f` хочет значение с плавающей точкой.

## Переменные

[оригинал](https://go.dev/doc/effective_go#variables)

Переменные можно инициализировать так же, как константы, но инициализатор может быть общим выражением, вычисляемым во время выполнения.

```
var (
    home   = os.Getenv("HOME")
    user   = os.Getenv("USER")
    gopath = os.Getenv("GOPATH")
)
```

> **Сейчас.** Режим GOPATH больше не основной способ собирать Go‑проекты. Зависимости описывают модулями. См. [How to Write Go Code](https://go.dev/doc/code) и [Using Go Modules](https://go.dev/blog/using-go-modules).

## Функция init

[оригинал](https://go.dev/doc/effective_go#init)

Наконец, каждый исходный файл может определить свою безаргументную функцию `init`, чтобы настроить нужное состояние. (На самом деле в каждом файле может быть несколько функций `init`.) «Наконец» значит именно наконец: `init` вызывается после того, как все объявления переменных пакета вычислили свои инициализаторы, а те вычисляются только после инициализации всех импортированных пакетов.

Кроме инициализаций, которые нельзя выразить объявлениями, обычное применение функций `init` — проверить или починить корректность состояния программы до настоящего выполнения.

```
func init() {
    if user == "" {
        log.Fatal("$USER not set")
    }
    if home == "" {
        home = "/home/" + user
    }
    if gopath == "" {
        gopath = home + "/go"
    }
    // gopath may be overridden by --gopath flag on command line.
    flag.StringVar(&gopath, "gopath", gopath, "override default GOPATH")
}
```
